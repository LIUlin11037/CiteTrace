# Offline RAG 检索配置：评测驱动的调参与推荐

> 范围：仅 offline 知识库（FinanceBench 子集：3 份 10-K / 571 页 / 21 题）
> 冻结：`agents/`、`judge.py`、落盘主 schema、online 全链路 —— 一行未改
> 结论措辞：**「在该子集上的推荐」**，不外推为普适最优

---

## 1. 实验设计

```
Stage A（检索层，¥0）      12 组配置 × 21 题 × 一次检索（depth=50）
                          指标：hit@5/10/20、recall@50、MRR、延迟
Stage B（端到端，¥8）      2 组配置 × 21 题，跑完整 offline 图
                          指标：引用存在率（程序）+ 对齐率 / 覆盖率（judge）
```

**k 不作为配置轴**：`search()` 内部按 `max(top_k, rerank_candidates)` 取候选再截断，
一次取 50 条即可算出所有 k 的命中率——k 是观察窗口，不是检索参数。

真实配置轴三条：embedding（本地 BGE-512 / API 多语言-1024）、rerank 候选池（关/50/100）、
query 扩展（0 / 3 条）。

## 2. Stage A 结果（21 题）

| 配置 | hit@10 | hit@20 | recall@50 | MRR | 延迟/题 |
|---|---|---|---|---|---|
| **api + p50 + exp3** | **61.9%** | 71.4% | **90.5%** | 0.399 | 3.48s |
| api + p100 + exp3 | 61.9% | 71.4% | 90.5% | 0.399 | 3.33s |
| api + p100 + exp0 | 61.9% | 71.4% | 76.2% | 0.395 | **1.60s** |
| api + p50 + exp0 | 52.4% | 61.9% | 76.2% | 0.327 | 1.12s |
| api + 无 rerank + exp3 | 52.4% | 76.2% | 85.7% | 0.348 | 2.56s |
| api + 无 rerank + exp0 | 38.1% | 52.4% | 76.2% | 0.191 | 0.42s |
| local + p100 + exp0 | 52.4% | 57.1% | 57.1% | 0.385 | 1.01s |
| local + p100 + exp3 | 52.4% | 52.4% | 52.4% | 0.362 | 2.26s |
| local + p50 + exp3 | 47.6% | 52.4% | 52.4% | 0.320 | 1.84s |
| local + p50 + exp0 | 28.6% | 28.6% | 28.6% | 0.221 | 0.65s |
| local + 无 rerank + exp3 | 23.8% | 33.3% | 47.6% | 0.113 | 1.24s |
| local + 无 rerank + exp0 | 14.3% | 19.0% | 28.6% | 0.042 | 0.11s |

### 三条结论

**① rerank 候选池 50 够用，翻倍到 100 收益为零**

`api+p50+exp3` 与 `api+p100+exp3` 的 hit@10 / recall@50 完全相同（61.9% / 90.5%）。
**多捞 50 条候选没有换来任何一个新增命中**，只是增加延迟。

**② 扩展与「扩大候选池」在 hit@10 上等价，但代价不同**

`api+p100+exp0`（1.60s）与 `api+p50+exp3`（3.48s）都是 61.9%。
差别在 recall@50：76.2% vs 90.5%（扩展 +14.3 点）。

**③ 本地 embedding 的省钱优势可忽略**

端到端单题 ¥0.26，其中 embedding 约 ¥0.01（<4%）。
为省这 4% 牺牲 28 个点的召回不划算——**embedding 是「质量杠杆」，不是「成本杠杆」**。

## 3. Stage B 结果（端到端 21 题）

| 指标 | exp3（+扩展） | exp0（对照） | Δ |
|---|---|---|---|
| 引用存在率 | **100.0%** | 85.7% | **+14.3** |
| 论断对齐率 | 82.5% | 84.8% | −2.4 |
| 知识点覆盖率 | **85.7%** | 73.8% | **+11.9** |

### 这组差异说明了什么

**exp0 有 3 题（fb-08 / fb-20 / fb-21）引用存在率为 0%** —— 报告一条可核验的引用都没发出。
加扩展后这 3 题全部回到 100%。

**但扩展让对齐率略降（−2.4）**：检索到更多相关页 → Writer 引用更多来源 →
证据链变长 → 出现更多「部分支持」的论断。

**净判断**：用 −2.4 点对齐换 +14.3 点引用与 +11.9 点覆盖，值得。
「引用真实存在」是这套系统的立身之本，「部分支持」是可接受的灰度。

## 4. 一个被平均分掩盖的发现：10 进 5 出

从基线（api 无 rerank 无扩展）到最优（api + p50 + exp3），hit@10 从 38.1% → 61.9%：

```
新进 top10：10 题
掉出 top10： 5 题
  00464  3 → 14
  00476  1 → 44
  01198  2 → 44
  01290  3 → 16
  01981  8 → 44
净收益：+5 题
```

**平均指标掩盖了 5 题被「优化」弄坏，其中 3 题掉到 44 名。**

这条对工程实践的启示：**只看均值会误导**。任何配置变更都需要 paired 分析，
并设「不显著变差」的门禁——否则你会在不知情的情况下用 5 个失败换 10 个成功。

## 5. 推荐配置

### balanced（默认推荐）

```bash
DR_EMBEDDING_PROVIDER=api        # 多语言 1024 维
DR_RERANK_PROVIDER=api
DR_RERANK_CANDIDATES=50
DR_QUERY_EXPANSION=true
DR_QUERY_EXPANSION_N=3
```

| 项 | 值 |
|---|---|
| 检索 | hit@10 61.9% / recall@50 90.5% |
| 端到端 | 引用 100% / 对齐 82.5% / 覆盖 85.7% |
| 延迟 | 检索 3.48s；端到端约 2 分钟/题 |
| 成本 | ≈ ¥0.26/题（扩展开销 <¥0.01） |

**适用**：默认全量使用。**不要用在**：延迟敏感的实时问答（检索就要 3.5 秒）。

### cheap（仅检索层验证，端到端未跑）

```bash
DR_EMBEDDING_PROVIDER=api
DR_RERANK_PROVIDER=api
DR_RERANK_CANDIDATES=100
DR_QUERY_EXPANSION=false
```

| 项 | 值 |
|---|---|
| 检索 | hit@10 61.9% / recall@50 76.2% / **1.60s** |
| 牺牲 | recall@50 −14.3 点；端到端引用率未验证（同类 exp0 为 85.7%） |

**适用**：延迟比召回重要时。**风险**：exp0 在 3 题上引用率归零，cheap 档可能重现。

### baseline（对照，不建议）

```bash
DR_QUERY_EXPANSION=false        # 其余同 balanced
```

引用 85.7% / 覆盖 73.8%。保留它作为 A/B 对照。

## 6. 边界与局限

| 项 | 说明 |
|---|---|
| 样本 | 21 题 / 3 份 10-K / 571 页；1 题 = 4.8 个点，不足以支撑显著性宣称 |
| 判分 | 对齐与覆盖由 LLM judge 给出，非人工评分；与公开基准不可横向比较 |
| 成本 | 单题成本来自历史测量，本次两组未单独埋点（扩展开销按 token 估算 <4%） |
| 显著性 | **所有配置差异在 n=21 下均不显著**（配对 bootstrap CI 跨零；McNemar p=0.302）→ 结论定位为机制观察，非效果证明 |
| 未覆盖 | p100+exp0 的端到端效果；DeepEval 交叉验证 |

## 7. 统计口径

```
n = 21 → 1 题 = 4.8 个百分点

配对 bootstrap（2000 次重采样，seed=20261031）：
  最优 vs 基线（hit@10）  +23.8%  [-9.5%, +57.1%]   不显著
  扩展 vs 扩大候选池      +0.0%   [0%, 0%]          完全等价
  扩展（同候选池）        +9.5%   [-9.5%, +28.6%]   不显著
  候选池 50→100           +9.5%   [-9.5%, +28.6%]   不显著

McNemar 精确检验：10 胜 / 5 负 / 6 平 → p = 0.302
```

**所以本实验能说的**：各机制救回/弄坏了哪些题、哪个配置点估计最好。
**不能说的**：「A 配置显著优于 B」。样本量不够，说了就是过度宣称。
