## 核查"弱强模型协作"这条 README 声明 → 又挖出两个真问题

  机制**确实实现了**（config.model_config_for 按角色路由；nodes.researcher_node 在

- **问题 1（配置层）**：用户 .env 里四个角色模型全为空 → 全部回落到 deepseek-chat →
  守卫条件 `researcher_model != critic_model` 不成立 → **升级路径从未触发过**。

  但 reasoner 属思考模式，**拒绝强制 tool_choice**：实测 langchain 的
  with_structured_output(method="function_calling") 走强制 tool_choice → HTTP 400
  "Thinking mode does not support this tool_choice" → 一旦按示例配置，critic/planner 结构化调用全崩
- 修复：
  1. core/llm.py 的 structured_output 改为自适应：先试强制 tool_choice，捕获含

  3. nodes.py 的守卫改为比较解析后的 (model, base_url) 对，同模型不同厂商也算有效升级
- 验证：reasoner 走降级路径首次 400→200 成功抽取（置信度 0.3）、第二次直接走缓存路径成功；
  smoke_test / smoke_eval 全绿
